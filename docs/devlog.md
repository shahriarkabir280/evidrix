# Devlog

One entry per part: what was built, what was measured, what surprised you, what's next.

## Part 1 — Foundation & ingestion (2026-10-09)

**Built**
- uv project (Python 3.12, lockfile), ruff, pytest, Makefile.
- Postgres 17 + pgvector 0.8.7 in Docker (port 5433), separate `evidrix_test` database.
- SQLAlchemy models and Alembic migration 0001: `users`, `documents`, `document_pages`, dev user seed.
- Content-addressed blob store (sha256 keys, atomic writes, path-traversal-safe keys).
- Extraction for PDF (per page, with page offsets), Markdown (front matter, title outside code fences) and TXT, with typed errors.
- `POST /documents`, `GET /documents`, `GET /documents/{id}`: size limit, extension + magic-byte checks, per-owner dedup, `processing → completed/failed` lifecycle.
- GitHub Actions CI: lint, migrations, `alembic check`, full test suite against a pgvector service container.

**Measured**
- 59 tests (unit + integration against real Postgres) in ~0.5 s.
- Mutation checks: removing the owner filter, the PDF magic-byte check, the empty-password decrypt, or the code-fence handling each fails exactly the intended test.

**Surprises**
- Alembic autogenerate emitted the `status` CHECK constraint twice for a non-native Enum. Autogenerated migrations need review.
- SQLAlchemy 2.1 bound a plain string UUID as VARCHAR in a raw `INSERT`; Postgres rejected it and the whole migration rolled back (transactional DDL).
- FastAPI file uploads need `python-multipart`, which the original roadmap's dependency list missed.
- Starlette's test client now prefers `httpx2` over `httpx`.
- Ollama defaults to a 4096-token context on this machine and silently shifts out overflow; the plan now sets 8192 and adds a prompt-size guard.

**Next**
