# Devlog

One entry per part: what was built, what was measured, what surprised you, what's next.

## Part 1 — Foundation & ingestion (2026-10-09)

**Built**
- uv project (Python 3.12, lockfile), ruff, pytest, Makefile.
- Postgres 17 + pgvector 0.8.7 in Docker (port 5433), separate `evidrix_test` database.
- SQLAlchemy models and Alembic migration 0001: `users`, `documents`, `document_pages`, dev user seed.
- Content-addressed blob store (sha256 keys, atomic writes, path-traversal-safe keys).
- Extraction for PDF (per page, with page offsets), Markdown (front matter, title outside code fences) and TXT, with typed errors.
- `POST /documents`, `GET /documents`, `GET /documents/{id}`: size limit, extension + magic-byte checks, per-owner dedup, `processing → completed/failed` lifecycle.
- GitHub Actions CI: lint, migrations, `alembic check`, full test suite against a pgvector service container.

**Measured**
- 59 tests (unit + integration against real Postgres) in ~0.5 s.
- Mutation checks: removing the owner filter, the PDF magic-byte check, the empty-password decrypt, or the code-fence handling each fails exactly the intended test.

**Surprises**
- Alembic autogenerate emitted the `status` CHECK constraint twice for a non-native Enum. Autogenerated migrations need review.
- SQLAlchemy 2.1 bound a plain string UUID as VARCHAR in a raw `INSERT`; Postgres rejected it and the whole migration rolled back (transactional DDL).
- FastAPI file uploads need `python-multipart`, which the original roadmap's dependency list missed.
- Starlette's test client now prefers `httpx2` over `httpx`.
- Ollama defaults to a 4096-token context on this machine and silently shifts out overflow; the plan now sets 8192 and adds a prompt-size guard.

## Part 2 — Baseline RAG (2026-10-11)

**Built**
- Pinned corpus: FastAPI 0.143.0 `tutorial/` (51 pages, MkDocs dialect normalized: code includes
  inlined, anchors/admonitions/HTML removed) + 4 Python 3.12 HOWTO PDFs; manifest with sha256.
- Structure-aware chunker (headings, paragraphs, atomic code blocks; ≤480 bge tokens; whole-sentence
  overlap within a section; exact character offsets; section paths; page ranges).
- `Embedder` protocol with bge-small-en-v1.5 (MPS/CPU), explicit query instruction, FakeEmbedder.
- Migration 0002: `index_versions` + `chunks` (vector(384), HNSW). Ingestion chunks and embeds in
  the same transaction; CLI `ingest-dir`, `reindex`, `search`.
- `LLMProvider` for any OpenAI-compatible endpoint (local Ollama, qwen3-vl:8b-instruct), JSON
  schema output, context guard, versioned prompt `answer_v1` with neutralized `<source>` tags.
- Answer validation: abstain before calling the model when there is no evidence, one retry on
  unusable JSON, citations kept only if they point at a retrieved source and appear in the text.
- `POST /chat` with citations, retrieved passages, timings, usage and config; `scripts/ask.py`.

**Measured**
- 670 chunks from 55 documents (median 299 tokens, max 480); ingest 17.6 s on MPS.
- HNSW vs exact top-5 agreement 1.000 — because at 714 chunks Postgres chooses a sequential scan.
- Local LLM: prompt reading ~157 tokens/s, generation ~15 tokens/s; each retrieved chunk adds
  ~1.8 s. A `/chat` call: embed ~0.4 s, retrieve ~0.04 s, generate ~10–13 s.
- 168 tests (unit + integration on real Postgres) + 2 live tests against Ollama.

**Surprises**
- MiniLM silently ignores everything after 256 tokens (cosine 1.0000 with/without extra text).
- FastAPI's docs keep code in separate files; without inlining includes the corpus had no code.
- pypdf dropped spaces between words for Type0/Identity-H fonts (4–8% of words glued in 3 of 4
  PDFs). Generated PDFs could not reproduce it; a real page is now a regression fixture and
  pdfminer.six extracts the text.
- bge's own config leaves the query prompt empty, so `encode_query()` would skip the instruction.
- Alembic autogenerate used `pgvector...VECTOR` without importing pgvector.
- qwen answered "admin dashboard?" without citing anything; citation validation turned it into an
  abstention.
- "Cleanup code after the response" retrieves Background Tasks instead of Dependencies with yield:
  a retrieval failure with a faithful answer.

## Part 3 — Retrieval engineering (2026-10-11)

**Built**
- Keyword search: generated `tsvector` column (section path weighted above body, `english` config)
  with a GIN index; OR query built with `plainto_tsquery`; `ts_rank_cd` ranking (ADR-0003).
- Reciprocal Rank Fusion (`1 / (60 + rank)`, ties broken by chunk id) over dense + keyword pools.
- Cross-encoder reranking (`cross-encoder/ms-marco-MiniLM-L-6-v2`) over the fused candidate pool.
- `RetrievalConfig` with presets `dense`, `hybrid`, `hybrid_rerank` (`configs/retrieval/*.toml`);
  one `retrieve()` entry point that times each stage and records each chunk's per-stage ranks.
- `POST /retrieve` (no LLM call) and per-request retrieval overrides on `/chat`, validated as a whole.
- Dense and keyword search share one function for the owner/status/index-version filters.

**Measured (10 hand-picked questions — a preview, not the evaluation)**

Rank of the document that answers the question, within the top 10:

| Question | dense | keyword | hybrid | hybrid+rerank |
|---|---|---|---|---|
| Cleanup code after the response has been sent | 10 | 3 | 4 | **1** |
| Return a 404 error | 3 | 1 | **1** | 2 |
| Read a value from a cookie | 1 | 2 | 1 | 1 |
| Allow requests from another origin | 1 | 1 | 1 | 1 |
| Accept an uploaded file | 1 | 1 | 1 | 1 |
| Sort strings case-insensitively | 1 | 1 | 1 | 1 |
| Write log messages to a file | 1 | 5 | 1 | 1 |
| Make a command-line option optional | 2 | 2 | **1** | 3 |
| What does `jsonable_encoder` do | 1 | 1 | 1 | 1 |
| Request body fails validation | 1 | 6 | 2 | **1** |
| **MRR@10** | 0.793 | 0.670 | 0.875 | 0.883 |

- Hybrid helped where one retriever was weak (cleanup: dense 10 → hybrid 4) and hurt where the
  keyword leg was noisy (validation: dense 1 → hybrid 2).
- Reranking fixed the hardest case (cleanup → 1, logit +4.55 vs +0.65 for the runner-up) and the
  hybrid regression, but demoted two correct top results (404, argparse). The model was trained on
  MS MARCO web queries, not technical docs; the Part 4 benchmark will decide whether it pays off.
- Latency: keyword search ~2–7 ms, fusion <1 ms, reranking 20 candidates 156 ms on MPS (786 ms CPU).

**Surprises**
- `websearch_to_tsquery` ANDs all words: 10 matching chunks for a natural question, 0 after adding
  one unknown word. OR + ranking matched 256.
- Keyword search finding nothing (e.g. `HTTPBasicCredentials`, absent from the tutorial) is a useful
  "probably unanswerable" signal; dense search always returns something plausible.

## Part 4 — Evaluation (2026-10-11)

**Built**
- Benchmark: 60 questions (20 factual, 10 identifier, 10 multi-hop, 8 distractor, 12 unanswerable)
  written from the source documents only, labeled with verbatim quotes; 36 dev / 24 test,
  stratified and fixed before any experiment. Single annotator; the second-annotator review was
  skipped.
- Label resolver (whitespace-insensitive quote matching → character ranges) and retrieval
  metrics (Recall, all-evidence, Hit, MRR, nDCG@5) with hand-computed tests; a chunk contains a
  quote when it holds at least half of it.
- Answer metrics: citation precision and abstention (deterministic); correctness and
  claim-level faithfulness from an LLM judge with versioned prompts.
- Runner with provenance, checkpointed answers and a separate judge process; report with
  bootstrap CIs and paired differences; the test split needs `--final`.

**Measured (dev split)**
- Judge calibration on 16 hand-labeled cases: llama3.1:8b 88% (v1) / 81% (v2), qwen3-vl 94% / 100%
  (not used: it writes the answers), gemma3:12b 100% / 94%. Judge: gemma3:12b with v1.
- hybrid_rerank vs dense: MRR +0.155 [+0.03, +0.29] and nDCG +0.117 [+0.01, +0.24] — significant.
  Correctness 0.862 → 0.914, faithfulness 0.923 → 0.963, citation precision 0.788 → 0.926,
  false abstentions 3 → 2 of 29: same direction, not significant at n = 29.
- hybrid vs dense: no significant difference on any metric.

**Surprises**
- The 10-question preview said reranking barely helped (MRR 0.875 → 0.883); the benchmark says
  it is the only significant gain.
- A valid citation is not a supported claim: hybrid answered the Kubernetes question (absent from
  the corpus) with "…including Kubernetes [2]" — [2] was a real source, the claim was invented.
- The first full run thrashed for ~5 hours on a 16 GB Mac: the evaluation process held the
  embedder and reranker in GPU memory next to the 12B judge. A child process for judging did not
  help (the waiting parent kept the memory); `os.execv` does. Ollama now runs with
  `OLLAMA_MAX_LOADED_MODELS=1`. Lesson: checkpoint long jobs, and budget memory before running.

**4F: abstention threshold**
- The threshold moved from one global setting into each preset: the top score is a cosine for
  dense, an RRF score for hybrid and a logit after reranking, so one number cannot fit all.
- dense: unanswerable top scores (0.71–0.79) sit inside the answerable range (0.69–0.89), so no
  threshold. hybrid_rerank: the two lowest logits are unanswerable (−4.22, −3.72), the lowest
  answerable is −1.95; threshold −2.84 (largest margin) catches 2 of 7 unanswerable questions and
  blocks none. The model already abstained on both, so quality is unchanged; 2 of 36 LLM calls
  are saved. The other five unanswerable questions retrieve on-topic passages (logits up to +5.7).

## Part 4b — Research papers (2026-10-11)

**Built**
- Corpus: eight retrieval/RAG papers from arXiv, chosen from 32 candidates for a license that
  allows redistribution (CC BY 4.0 / CC BY-SA 4.0), pinned by version, recorded with license in
  the manifest. Documents belong to a collection (docs / papers); each benchmark searches its own.
- PDF reading: ligatures spelled out; hyphen kept when a compound continues with hyphens; numbered
  section headings detected (also when sharing a text box with the paragraph, after a table of
  contents, References and lettered appendices).
- Paper benchmark: 24 questions (incl. a new `table` type and cross-paper multi-hop), 13 dev / 11
  test. `exclude_references` retrieval option and `--benchmark papers` in the runner.

**Measured**
- Before fixing: two-column order already correct; ligatures 77–126 in three papers; PDF chunks had
  no section path. After: 0 ligatures; 86–98% of PDF chunks in a section. The documentation
  benchmark moved within noise (MRR −0.003).
- Papers (dev, hybrid_rerank): Recall@5 0.712, MRR 0.712, correctness 0.818, faithfulness 1.000,
  abstention 2/2 with no false abstentions. Excluding references: Recall@5 0.803, answers identical.

**Surprises**
- The predicted problem (two-column reading order) did not exist; the unpredicted ones
  (ligatures, headings sharing a text box, a table of contents breaking the numbering) did.
- Two identifier questions scored recall 0 but were answered correctly: the papers state the
  answer in several places and the label covers one. Labels left frozen (extending them from
  system output would bias the benchmark); future labels should mark every location.
- A wrong number read from a scrambled table was graded fully faithful, because the number is in
  the source.
